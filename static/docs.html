Getting started

Interview Memory Coach

An AI interview system that remembers candidates across sessions. Upload a job description and resume, run a live streaming interview, receive a scored report — and when the same candidate returns, the AI recalls everything: strengths, gaps, and past performance.

The three-view flow

1
Intake

Set up the candidate, upload the JD and resume, review the fit analysis before the interview begins.

2
Interview

Conduct a streaming AI interview with text or voice answers. Prior session memory shapes question depth in real time.

3
Report

View skill scores, gap analysis, the candidate memory graph, and a hiring recommendation. Export or delete candidate data.

◈
Memory persists across sessions

When a candidate returns for a second interview, the AI automatically loads their prior scores and known gaps. No manual setup required.

Getting started

Quick start

Prerequisites

  • Python 3.10+
  • A Groq API key — free at console.groq.com

Installation

git clone <repo-url>
cd Interview-memory-coach
pip install -r requirements.txt
cp .env.example .env
# Edit .env: add GROQ_API_KEY=gsk_...
uvicorn server:app --reload --port 8000

Open http://localhost:8000 in your browser.

First interview

1
Enter a Candidate ID

Type a unique ID like alice_jones. This is the memory key across sessions.

2
Paste the job description

Full JD text — skills, experience requirements, responsibilities.

3
Upload or paste the resume

PDF drag-and-drop or paste text directly.

4
Review the fit analysis

The match score and gap tags appear once both fields are populated.

5
Click Start Interview

The AI builds the candidate's entity graph (~5s) and begins the session.

⚡
First-run delay

On the very first Start Interview, Cognee runs ~20 database migrations (~5–8s). Subsequent sessions skip this and start immediately. Open the app a minute before a demo to let migrations complete quietly.

Using the app

Intake view

Candidate ID

A unique identifier used as the memory key. The same ID across sessions is what enables cross-session recall.

  • Allowed: letters, numbers, underscores, hyphens
  • Maximum 40 characters; case-sensitive
  • Examples: alice_jones, candidate-001, jsmith_2026

Candidate selector

The dropdown lists all candidates with prior sessions. Select one to load history, or click + New to type a new ID. When a returning candidate is selected, a purple chip shows the session count — the AI uses this context automatically.

Job description

Paste the full JD text. The system extracts required skills, experience levels, and role expectations. Recommended length: 200–2000 words.

Resume

  • PDF upload — Drag-and-drop or click the upload area. Requires a PDF with selectable text (not a scanned image). Max 10 MB.
  • Paste text — Use the text area directly when PDF extraction fails.
✓
Check PDF extraction

After uploading, glance at the character count next to the field. Under 100 characters usually means the PDF is a scanned image — paste the text directly instead.

Start Interview button

Enabled once Candidate ID, JD, and Resume are all filled. Clicking it runs:

  1. Intake agent — extracts entities from JD + resume
  2. cognify() — builds the candidate entity graph in Cognee
  3. recall() — loads prior session context (returning candidates only)
  4. Question generation — tailored to JD↔resume gaps
Using the app

Interview session

Prior memory banner

For returning candidates, a blue banner at the top of the chat shows which prior context was loaded:

Memory active · Jun 15 2026
Candidate scored 2/5 on distributed systems.
Probing this area deeper this session.

Question queue

The right panel lists all questions. Completed questions are checked off in green. The queue is generated at session start and does not change mid-session.

Answering with text

Type in the text field at the bottom and press Enter or click Send. The AI evaluator responds in real time — streamed character by character — with commentary followed by the next question.

Answering with voice

  1. Click the microphone button to begin recording
  2. Speak your answer naturally
  3. Click stop when done
  4. Review the Whisper transcript — edit if needed
  5. Click Submit

Ending the interview

After all questions are answered, the Generate Report button activates in the right panel. The analysis agent scores each answer (~5–10s).

◈
Memory writes in the background

After each answer, the Q&A pair is stored in Cognee's graph asynchronously — it never delays the next question from appearing.

Features

How memory works

Five Cognee lifecycle APIs power the memory system, each with a distinct role in the interview workflow.

APIWhen calledWhat it does
cognify() Session start Processes JD + resume into a knowledge graph: Candidate, Skills, Role entities and their relationships. Persists across sessions.
remember() After each answer Stores the Q&A pair in the candidate's memory graph in the background. Enables future sessions to recall specific answers.
recall() Session start (returning) Retrieves prior scores, gaps, and session context. Produces the "Memory active" banner and shapes question depth.
memify() Session end Writes role-level quality metadata back to the graph (QuestionTemplate → performed_well_on → Role).
forget() GDPR button Permanently wipes all graph and vector store entries for the candidate, plus the local JSON sidecar entry.

Storage locations

  • Cognee graph + vectors — NetworkX graph and LanceDB vectors inside the Python venv (~/.cognee/). Powers semantic recall() queries.
  • JSON sidecar — ~/.cognee_coach/sessions.json. Structured index for deterministic lookups: candidate list, session history sorted by date, report scores.
◈
Memory survives server restarts

Both stores are on disk. Restarting the server preserves all candidate memory — only the in-memory active interview session state is lost on restart.

Microphone permissions

When you first click the microphone, the browser prompts for access. Click Allow. If you previously denied:

  • Chrome: Lock icon in address bar → Microphone → Allow
  • Firefox: Preferences → Privacy → Permissions → Microphone
  • Safari: Safari → Settings for This Website → Microphone → Allow
⚡
HTTPS or localhost required

MediaRecorder is blocked on plain HTTP for non-localhost origins. The app works at http://localhost:8000. For network exposure, use HTTPS.

Recording tips

  • Speak at a normal pace, ~50cm from the microphone
  • Minimize background noise — Whisper handles accents well but noise degrades accuracy
  • After transcription, edit the text before submitting if needed

Fit analysis

The fit analysis band appears in the Intake view after both the JD and Resume fields have content. It runs automatically 500ms after you stop typing.

What the band shows

FieldDescription
Match score0–100 alignment between JD requirements and resume. A signal for interview focus, not a hiring decision.
Role titleThe role the system infers from the JD text.
Experience hintEstimated level from JD language (junior / mid / senior).
StrengthsSkills the resume demonstrates that the JD requires — cyan tags.
GapsSkills the JD requires that are absent in the resume — red tags.
✓
Gaps drive question selection

The interview agent generates more probing questions for identified gaps. A candidate with a "distributed systems" gap will receive more targeted questions in that area.

Troubleshooting

Session start is slow

Cause: On the first-ever run, Cognee executes ~20 Alembic migrations (~5–10s).

Fix: Subsequent starts skip migrations. For demos, open the app 1–2 minutes before presenting — let the health endpoint respond before starting an interview.

Voice input not working

  1. Check browser microphone permissions (lock icon → Microphone → Allow)
  2. Ensure you're on http://localhost or https:// — plain HTTP is blocked for non-localhost
  3. Check the OS microphone isn't muted
  4. Try Chrome if using a different browser

PDF not extracting text

Cause: PyMuPDF extracts selectable text. Scanned PDFs (image-only) return empty or garbage text.

Fix: Paste the resume text directly into the text area.

"Session not found" error

Cause: Active sessions are in server memory. A server restart loses in-progress sessions.

Fix: Start a new interview from Intake. Candidate memory in Cognee and the JSON sidecar is not affected by restarts.

Fit analysis band not appearing

  • Both JD and Resume must have content
  • The band appears 500ms after you stop typing — wait briefly
  • If the Groq API returns an error the band stays hidden — check server logs for [analyze] errors

Cognee retry warnings in logs

Warnings like "Retrying acreate_structured_output in 8.5 seconds" are Cognee's internal graph extraction retrying in the background. They do not block the interview UI. See .docs/architecture-decisions.md ADR-005 for full context.
